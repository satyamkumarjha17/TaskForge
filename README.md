# TaskForge

TaskForge is a task-management application organized around users, workspaces, boards, and tasks. The Phase 1 implementation uses a React/TypeScript client, an Express/TypeScript API, MySQL 8, and Prisma.

## Features

- Registration, login, logout, and persisted cookie sessions
- CSRF protection, rate limiting, server-side validation, and ownership checks
- Workspace, board, and task CRUD
- Three fixed Kanban statuses: To Do, In Progress, and Done
- Task priority and date-only due dates
- Responsive Workshop Ledger interface

## Stack

React, TypeScript, Vite, Tailwind CSS, React Router, Axios, Lucide React, Node.js, Express, Prisma, MySQL 8, JWT, bcrypt, Zod, Vitest, Supertest, and React Testing Library.

## Requirements

- Node.js 22.12.x, 24.x, or 26+
- npm 10+
- MySQL 8

## MySQL setup (Windows PowerShell)

Run these statements in MySQL as an administrator. Use a strong local password and keep it out of source control.

```sql
CREATE DATABASE taskforge CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE taskforge_shadow CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'taskforge_app'@'localhost' IDENTIFIED BY 'REPLACE_WITH_A_STRONG_PASSWORD';
GRANT SELECT, INSERT, UPDATE, DELETE ON taskforge.* TO 'taskforge_app'@'localhost';
CREATE USER 'taskforge_migrator'@'localhost' IDENTIFIED BY 'REPLACE_WITH_A_DIFFERENT_STRONG_PASSWORD';
GRANT ALL PRIVILEGES ON taskforge.* TO 'taskforge_migrator'@'localhost';
GRANT ALL PRIVILEGES ON taskforge_shadow.* TO 'taskforge_migrator'@'localhost';
FLUSH PRIVILEGES;
```

Copy `server/.env.example` to `server/.env` and set `DATABASE_URL`, `DIRECT_URL`, `SHADOW_DATABASE_URL`, `JWT_SECRET`, `CLIENT_ORIGIN`, and `COOKIE_SECURE`. `DATABASE_URL` must use the restricted runtime user; `DIRECT_URL` uses the separate migration user and is only needed for Prisma migration commands. Use a JWT secret with at least 32 characters. URL-encode reserved characters in database usernames or passwords (for example `@`, `:`, `/`, `#`, and `%`). For local HTTP development, `COOKIE_SECURE=false` is required. Production must use HTTPS and `COOKIE_SECURE=true`.

Example database URL:

```text
DATABASE_URL="mysql://taskforge_app:APP_PASSWORD@localhost:3306/taskforge"
DIRECT_URL="mysql://taskforge_migrator:MIGRATION_PASSWORD@localhost:3306/taskforge"
SHADOW_DATABASE_URL="mysql://taskforge_migrator:MIGRATION_PASSWORD@localhost:3306/taskforge_shadow"
```

## Install and run on Windows

First create the MySQL database and the two database users using the SQL statements above. Then open the project folder in VS Code and run this from a PowerShell terminal:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\setup.ps1
```

The script creates local environment files from the examples if they do not exist, opens `server/.env` for configuration, installs the exact dependencies from the lockfile, validates the Prisma schema, generates Prisma Client, applies the initial migration, and starts both applications. It stops immediately if a required step fails.

If you prefer to run the steps manually from the repository root:

```powershell
Copy-Item server/.env.example server/.env
Copy-Item client/.env.example client/.env
# Edit server/.env and set real MySQL credentials and a JWT secret of at least 32 characters.
npm ci
npm run db:validate
npm run db:generate
npm run db:migrate
npm run dev
```

The client runs at `http://localhost:5173`; the API runs at `http://localhost:4000`. Vite proxies `/api` to the API during development. In production, serve both applications behind one origin or set `VITE_API_BASE_URL` to the API base URL and configure `CLIENT_ORIGIN` to the exact frontend origin. For cross-site cookies, use `COOKIE_SAME_SITE=none` and `COOKIE_SECURE=true` over HTTPS.

```powershell

```

Database commands:

```powershell
npm run db:generate
npm run db:migrate
npm run db:deploy
```

`db:migrate` creates a migration from the Prisma schema using Prisma's migration engine. Review and commit the generated migration directory. Never run a destructive reset against a database containing user data.

## Architecture

- `client/src/pages`: route-level screens
- `client/src/components`: shared UI and domain components
- `client/src/context`: authenticated user and CSRF state
- `client/src/services`: typed API access
- `server/src/routes`: HTTP route definitions
- `server/src/controllers`: request/response handling
- `server/src/services`: domain operations and ownership-scoped queries
- `server/src/validators`: Zod input schemas
- `server/prisma`: schema and migration history generated by `npm run db:migrate`

Every workspace, board, and task operation is scoped to the authenticated user. The API returns `{ data }` for success and `{ error: { code, message, details? } }` for failures. Cookie-authenticated state-changing requests require the `X-CSRF-Token` header and a matching token cookie, plus an allowed `Origin`.

## API overview

- `GET /api/v1/auth/csrf`, `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`, `GET /api/v1/auth/me`
- `GET|POST /api/v1/workspaces`, `GET|PATCH|DELETE /api/v1/workspaces/:id`
- `GET|POST /api/v1/workspaces/:workspaceId/boards`, `GET|PATCH|DELETE /api/v1/boards/:id`, `GET /api/v1/boards/recent`
- `GET|POST /api/v1/boards/:boardId/tasks`, `GET|PATCH|DELETE /api/v1/tasks/:id`
- `GET /api/v1/health`

## Troubleshooting

- If the API refuses to start, verify all required variables in `server/.env`.
- If Prisma cannot connect, verify MySQL is running and the database URL credentials are correct.
- If browser requests fail, confirm `CLIENT_ORIGIN` exactly matches the client origin and that both client and server are running.
- If cookies are not stored locally, use `COOKIE_SECURE=false` on HTTP. Do not use that setting in production.
